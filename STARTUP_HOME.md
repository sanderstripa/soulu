# Startup, New Tab and Home

Independent per-profile settings use `startupMode/startupUrl`, `newTabMode/newTabUrl` and `homeMode/homeUrl` in `Profiles/<id>/soulu-settings.json`. Startup supports `continue`, `soulu`, `custom`, and `blank`. New Tab and Home support `soulu`, `custom`, and `blank`. Persisted legacy `startPageMode/startPageUrl` migrate to Startup only; old controls remain compatible with Startup. Invalid or empty stored custom URLs fall back to the local Soulu page; UI mutations reject non-web addresses, credentials, whitespace, and executable schemes.

The default experience is the packaged Soulu page for Startup, New Tab and Home. The default page is intentionally minimal: the Soulu mark, a central query/URL field, a compact weather surface and a favorites launcher. The center search has an explicit per-query engine switch between Google and Perplexity; Google is selected when the page opens. URL-like input still follows the normal Soulu navigation boundary, while plain queries are sent to the selected provider. The right side of the search field exposes voice input when the embedded engine provides the Web Speech API. There is no wallpaper, greeting, clock, recent-sites feed or duplicate wordmark.

The favorites launcher is backed by the existing `homeShortcuts` profile setting. Shortcuts are ordered, limited to 12, and support add, edit, delete and moving left through the existing Settings/Home bridge. The home page renders them as a compact three-column launcher and opens the chosen destination in the current Soulu tab. Favicons are requested directly from a user-selected shortcut's origin, without a referrer; offline/error uses a generated local monogram. No third-party favicon service is used.

Weather remains optional through `homeShowWeather` and uses the user-selected `homeWeatherCity`. The compact surface shows condition, temperature and city; clicking it expands current conditions, apparent temperature, wind, humidity, hourly conditions and a seven-day forecast. The page uses the public Open-Meteo geocoding and forecast endpoints asynchronously and keeps a short in-memory cache; weather never blocks the local Home shell. No API key, secret or automatic geolocation is used. If no city is configured or the service is unreachable, the page keeps working and shows an honest local fallback state.

`+`, Ctrl+T, sidebar and Overview creation use New Tab and focus an empty omnibox on the Soulu page, without triggering suggestions for an internal URL. Alt+Home and `browser.home` use Home in the current tab. No Home button is forced into the existing toolbar. The last-tab setting retains Startup when enabled and a blank replacement when disabled. Pending tabs count as tabs; removing one selects an existing visible tab before creating a replacement. Closing the last incognito tab returns to the normal profile and disposes private state.

`soulu://home` is a browser navigation alias for the exact packaged `file:///.../ui/home.html`, using the existing local internal-page architecture. It is not a globally registered scheme and never starts a local web server. Blank uses packaged `start.html`. HTML, CSS, JS, typography, branding and fallback icons are local; only user-requested weather/favicons and the selected external search provider leave the packaged page.

The Home bridge is distinct from the privileged shell/settings bridge. Only the exact main home document attached to its native tab can invoke `home.get`, `home.set`, `home.navigate` and `home.weather`. The native caller's tab determines profile and privacy; no caller-supplied profile ID is accepted. The response exposes only Home settings, not passwords, bookmarks or other profile data. Shortcut names and city text use DOM text nodes. HTTP(S) shortcut URLs are validated natively. Home URL navigation reuses the omnibox boundary.

`homeShortcuts`, `homeWeatherCity` and individual `homeShowLogo/Search/Weather/Shortcuts/Background` switches use the existing atomic profile JSON writer. The background switch controls subtle surfaces; there is no custom image/file access. Incognito begins with a copy of the normal page settings and only mutates an in-memory private copy, cleared when the final private tab closes. The normal profile file is never written by Home's private bridge.

A graceful close writes ordered normal HTTP(S), Soulu and blank tab URLs and the last normal selected index to each profile's `soulu-session.json`. Startup `continue` restores only the launching normal profile, without an extra New Tab. Incognito and settings tabs are excluded. This is URL/order/selection restore, not navigation-history, scroll-position or crash-recovery restore. Missing or invalid snapshots fall back to Soulu. Restored URLs are validated, and snapshot size is bounded at 100 tabs.

Validation is implemented in `scripts/test-cef-home-pages.py` and runs against the native CEF executable. The release workflow gates on these checks plus the existing storage, profiles/passwords, permissions/adblock, navigation/popups, bookmarks/Overview, Reader and layout suites. The `native_only` workflow input can build and test a reviewable runtime without producing an installer. Both keep CEF 154.0.32 / Chromium 154.0.8037.58 pinned.
